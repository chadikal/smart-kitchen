# Smart Kitchen

Mobile-first cooking and baking app with an English and Arabic interface, and a small NestJS API. Milestone 1 has navigation, localization, and a health check. Milestone 2 adds the Prisma recipe catalog. Public recipe browsing and detail endpoints are available. Authentication and recipe editing are not implemented yet.

## Requirements

- Node.js 22.13 or newer. This project was created with Node.js 26.1.0 and npm 11.13.0.
- npm 10 or newer, included with that Node.js release.
- PostgreSQL 16 or newer, only when you are ready to connect the API to a database. The health check does not need a running database.
- Expo Go on a phone, or a local Android emulator, to run the mobile app. An iOS Simulator requires macOS.

## Install

From the repository root in PowerShell:

```powershell
npm install
```

`npm install` installs both workspaces. The API `postinstall` is not required; Prisma Client is generated by the API build, type-check, and test scripts.

Generate the client once if you want to open the API in an editor before those scripts run:

```powershell
npm run prisma:generate
```

## Environment

```powershell
Copy-Item apps\api\.env.example apps\api\.env
Copy-Item apps\mobile\.env.example apps\mobile\.env
```

Edit `apps\api\.env` and replace the database user and password. The example URL is:

```text
postgresql://postgres:postgres@localhost:5432/smart_kitchen?schema=public
```

The catalog migrations are `apps/api/prisma/migrations/20261022180000_init_recipe_catalog` and `apps/api/prisma/migrations/20261024153000_seed_provenance`. They have been applied to the disposable `smart_kitchen_migration_test` database, not to `smart_kitchen`. Relationships, access, measurement units, translation completeness, fallback, and the development seed are described in `apps/api/prisma/DATA_MODEL.md`.

Seed the test database explicitly from `apps/api`:

```powershell
npm run prisma:seed
```

That command does not run on startup or during migration. It uses `MIGRATION_TEST_DATABASE_URL` only when that URL is a local loopback host, port 5432, database `smart_kitchen_migration_test`, and `schema=public` with no other connection options. It updates rows it has already marked in `seed_provenance`. Unmarked rows are left unchanged. It will not write to `smart_kitchen`.

`npm run prisma:reconcile-seed` compares the current sample catalog with rows already stored in the test database and prints mismatches. It does not write. `npm run prisma:reconcile-seed -- --apply` records provenance for an exact match and leaves every stored field unchanged.

`apps\mobile\.env` sets `EXPO_PUBLIC_API_URL`. `localhost` works in a browser on the same computer. A physical phone needs your computer's LAN address, for example `http://192.168.1.20:3000`.

Do not commit `.env` files.

## Run the API

```powershell
npm run dev:api
```

The API listens on port 3000 unless `PORT` is set. Check it from another PowerShell window:

```powershell
Invoke-RestMethod http://localhost:3000/health
```

The response is `{ "status": "ok" }`. Prisma Client is configured, and it connects on the first query. Starting the API and calling `/health` does not require PostgreSQL to be running.

`GET /recipes` and `GET /recipes/:slug` browse published public recipes. Filters, language fallback, and decimal quantities are documented in [apps/api/README.md](apps/api/README.md).

## Run the mobile app

```powershell
npm run dev:mobile
```

Then:

- Press `w` to open the web app.
- Press `a` to open Android.
- Scan the QR code with Expo Go for a physical device.

The app opens on Home, Discover, My Kitchen, My Recipes, and Profile. Profile switches between English and Arabic. Arabic uses right-to-left layout in the current session through Expo Router's locale direction and a root layout direction. `expo-localization` also allows RTL when the device language is Arabic.

## Checks

From the repository root:

```powershell
npm run lint
npm run typecheck
npm test
npm run build
```

- `lint` runs ESLint in the mobile app and oxlint in the API.
- `typecheck` runs `tsc --noEmit` in both workspaces.
- `test` runs the mobile locale tests and the API unit and end-to-end health tests.
- `build` compiles the API with Nest and exports the mobile web bundle.

The mobile lint script calls ESLint directly. `expo lint` does not resolve the workspace ESLint install from the hoisted Expo CLI.

## Layout

```text
apps/mobile   Expo Router app
apps/api      NestJS API, Prisma, and PostgreSQL configuration
```

Shared TypeScript strictness lives in `tsconfig.base.json`. The mobile app extends Expo's base config and repeats those strict flags. The API extends `tsconfig.base.json` and keeps Nest's CommonJS compiler options, including `strictPropertyInitialization` disabled for dependency injection.

## Versions

- Expo SDK 58, React Native 0.88, React 19.3
- Expo Router and React Native Paper
- i18next, react-i18next, and expo-localization
- NestJS 12 with Jest
- Prisma ORM 7 and PostgreSQL

Prisma ORM 8 was still a release candidate when this foundation was created, so the API stays on Prisma 7. The NestJS 12 ESM starter uses Vitest; this API uses the CommonJS starter so the tests run on Jest.
